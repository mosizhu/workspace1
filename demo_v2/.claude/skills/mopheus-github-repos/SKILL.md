## Mopheus Workflow Return

This skill is a sub-procedure inside a larger Mopheus agent run. Its completion language ("done", "finished", "task complete") applies only to the skill's own steps.

After the skill's substantive work is complete, return to the runtime Workflow in the main instructions and continue with the next required step, including any final comment, metadata update, label update, status transition, or user-facing response.


# Code Workflow

Full workflow for writing code on a ticket. **You MUST complete all 8 steps.** Stopping after push without syncing the PR leaves the work unlinked to the ticket. The local worktree may be cleaned up after your turn ends — unpushed local changes will be lost.

## Steps

```bash
# 1. Checkout — creates an isolated worktree with a topic branch
mopheus repo checkout <url> --branch <branch-type>/issue-<github-issue-number>-<short-description> --output json

# 2. Work — cd into the returned path, implement changes using TDD when practical

# 3. Commit — use git-commit-message skill to generate the message, then commit
git add -A
git commit -m "<message generated by git-commit-message skill>"

# 4. Push (REQUIRED before finishing — local worktree may be cleaned up)
git push -u origin <branch-name>

Always push the explicit current branch name; do not use `HEAD:<branch-name>` as a push refspec. After pushing, verify the remote branch SHA with `git ls-remote origin "refs/heads/<branch-name>"` and compare it with `git rev-parse HEAD`.

# 5. Post branch setup comment on the Mopheus ticket (REQUIRED)
#    Record the repository, branch name, and current commit SHA. Do not post local paths.

# 6. Create PR targeting main
gh pr create -R <url> --title "..." --body "..." --base main

# 7. Sync PR to ticket (REQUIRED)
mopheus repo pr sync --repo <url> --number <N> --title "..." --state open --ticket <ticket-id> --auto-link --output json

# 8. Post completion comment on the Mopheus ticket
```

## Branch Naming

- When the task is backed by a GitHub issue: `{branch-type}/issue-{github-issue-number}-{short-description}`
  - Example: `fix/issue-42-login-timeout`, `feat/issue-103-add-dark-mode`
  - Use the **GitHub issue number**, not the Mopheus ticket number.
- When the task has no GitHub issue: choose a concise branch name that reflects the Mopheus task and change type.
- **Never commit directly on main.**

## How checkout works

`mopheus repo checkout` creates an isolated worktree from a bare cache. The worktree branch is unique to your agent task — other agents and the main branch are unaffected.

If an existing task worktree has local changes or unpushed commits, checkout refuses to overwrite it. Use `--force` only when those changes should be discarded.

# Issue Workflow

Create GitHub issues and sync them to Mopheus tickets.

## Steps

```bash
# 1. Create issue
gh issue create -R <url> --title "..." --body "..."

# 2. Sync issue to ticket (REQUIRED)
mopheus repo issue sync --repo <url> --number <N> --title "..." --state open --ticket <ticket-id> --auto-link --output json
```

# PR Review

## Sync Existing PR

Use this before or during PR review when a PR already exists and the task only needs to mirror/link it back to Mopheus.

```bash
# 1. Check whether the PR is already mirrored
mopheus repo pr list --repo <url> --number <N> --output json

# 2. Sync or update the PR mirror record
mopheus repo pr sync \
    --repo <url> --number <N> --title "..." --state open \
    --author <login> --head <ref> --base <ref> \
    --ticket <ticket-id> --auto-link --output json

# 3. Confirm the ticket link exists
mopheus repo links --repo <url> --type git_pull_request --number <N> --output json
```

- PR not found in Mopheus → run `mopheus repo pr sync`.
- PR exists but state/title/head/base changed → run `mopheus repo pr sync` again to update it.
- PR exists and is already linked to the ticket → do not duplicate the link.
- PR exists but is not linked → use `--ticket <ticket-id> --auto-link` on sync, or link manually with `mopheus repo link` using the PR UUID from the sync output.

## Review Comments

When responding to PR review comments, handle one thread at a time:

1. Fix the code or reject with rationale.
2. Reply to the review comment (REST reply endpoint, URL must include PR number).
3. Resolve the review thread (GraphQL `resolveReviewThread` mutation — no REST endpoint).
4. Never use PATCH on a comment you did not author — it overwrites the original content.
5. Always reply first, then resolve. A resolved conversation with no reply is incomplete.

# Rules

- Always use `mopheus repo checkout`. Never use `git worktree add` directly.
- Use `--ref <branch|sha>` to checkout a non-default branch.
- Always use `--output json` on `mopheus` commands so results are machine-parseable.
- Do NOT skip PR sync. A pushed branch without a synced PR is invisible to the ticket.
- Always sync the issue to the ticket after creation. Use `--auto-link` to automatically link related entities.
- You MUST commit and push to remote before finishing — unpushed local changes will be lost.

# Troubleshooting

### Checkout failed

```bash
# Is the repo registered?
mopheus repo list --output json
```

- **Repo not registered** → the repo must be added first (`mopheus repo add <url>`)
- **"cannot resolve default branch"** → the bare cache may be stale; try again
- **"sync bare cache: git fetch failed"** → network or auth issue; check if the git remote URL is accessible from this machine
- **Permission denied on worktree** → the worktree path may be owned by a different task; don't reuse paths manually

### PR sync failed

```bash
# Check if PR already synced
mopheus repo pr list --repo <url> --number <N> --output json
mopheus repo links --repo <url> --type git_pull_request --number <N>
```

- PR already exists and state matches → skip sync
- PR not found → make sure `gh pr create` succeeded and the PR number is correct

### Agent stuck waiting for permission

If the agent reports "permission to write file not granted", the Edit tool may be blocked. Use Read + Write as a workaround — read the full file, modify it, write it back.
